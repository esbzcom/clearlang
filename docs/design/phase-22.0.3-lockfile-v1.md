# Phase 22.0.3 - Lockfile v1 Deterministic Workflow

## Status
Design lock target for `22.0.3` in `docs/TODO.md`.

## Goal
Evolve lockfile v0 (direct-only pins) into a full deterministic lockfile for transitive package resolution.

## Canonical File
- Filename: `clg.lock.json`
- Schema version: `1`
- Generated by CLI workflow (not hand-authored in production flow)

## Schema (v1)
```json
{
  "schema_version": 1,
  "resolver_version": 1,
  "roots": [
    {
      "name": "app",
      "dependencies": [
        { "name": "std::core", "requirement": "^1.0.0" }
      ]
    }
  ],
  "packages": [
    {
      "id": "std::core@1.0.0",
      "name": "std::core",
      "version": "1.0.0",
      "digest": "sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
      "abi_id": "std-core-abi-v1",
      "dependencies": [
        "std::host@1.0.0"
      ]
    }
  ]
}
```

## Workflow Lock
1. `clg pkg lock --generate`
   - creates a full v1 lockfile from canonical metadata and advisory policy inputs.
2. `clg pkg lock --update`
   - updates lockfile from current roots + policy + advisory constraints.
3. Strict advisory determinism:
   - `clg pkg lock --compiler-mode strict` requires `--advisory-as-of <RFC3339_UTC>`.
   - strict mode requires signed advisory envelope + trust-policy verification when advisory input is present.
4. `clg build --compiler-mode strict`
   - consumes lockfile as source of truth and rejects drift.

## Determinism Rules
1. `roots` sorted by `name`.
2. `roots[].dependencies` sorted by `name`.
3. `packages` sorted by `id` (`name@version`).
4. `packages[].dependencies` sorted by `id`.
5. Canonical serializer preserves this sorted shape and stable key ordering.
6. Replay with identical inputs must produce byte-identical lockfile and identical hash.

## Compatibility Rules
- v0 lockfile remains accepted only during migration window defined by `22.0.4`.
- strict mode in final production profile requires v1.
- unsupported schema versions fail closed.
